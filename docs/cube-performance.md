# Cube 性能与验证

主实现目前采用混合分派：K≤128、M/N≥256、M*N*K≥2^24 时使用 Cube，其他尺寸沿用 Vector。该阈值只依据已测的大型短 K 数据，尚不声称最优。Cube 数值计算和两级归约全部在 NPU 完成；Host 负责 tiling、工作内存与启动。普通调用同步完成后释放工作内存，图捕获将每次调用的缓冲保留到图销毁。

主实现 SHA256 `32b012d2817efebaee75b5d649147fa9a77ce6740737deca8fa3da805e9e8b87` 已完成目标 ASC 编译/链接与真机验证，尚未获得新赛事平台结果。此前赛事 15/15 对应 Vector 版本 `e8ec315`，不能继承为新主实现的赛事结论。

## 主实现验证

本地 456 组 CPU 检查通过，包括 Clang Host 地址空间、ASan/UBSan、线程集合执行、输入保护、输出边界与重复确定性。CPU 的 Matmul 使用 FP64 点积，不模拟 Cube 硬件舍入、同步或图捕获。

真机 280 个正确性、96 个长 K/分区边界、80 个性能边界用例，在普通、首次冷捕获、同图三次调用、双 stream 图重放、独立 C++ 动态库冷捕获五种模式分别全部通过。24 个大型短 K 用例也通过相同五种模式及 benchmark。独立 FP64 核验最大误差/允许误差为 0.003739361，大型集合为 0。

主 runner 的 17 组资源报告分配/释放各 1,296 个缓冲，登记 160 次图销毁回调，408 次普通同步，无内部 ACL 错误；捕获期间 Host 内部不执行 stream 同步。Vector fallback 不分配这些缓冲。另有独立动态库验证，不含内部 tracing 计数。源码中的 Vector 计算与 Host 分区逻辑和 `e8ec315` 完全一致。原始汇总见 [cube-performance-data.json](cube-performance-data.json)。

## 主实现同轮性能对照

在同一台 NPU 上顺序重跑新主实现与 `e8ec315` 的 Vector 对照，使用完全相同的 24 个大型短 K 输入，两组 profile 的输出均独立核验通过。Vector 记录 288 次 kernel，混合版记录 576 次 kernel；每例各预热 2 次、测量 10 次。混合版取 Scores 开始至 Finish 结束的区间，包含两 kernel 的间隔；不使用 Host wall time 代替设备时间。

| B,M,N,K | Vector 中位数 / µs | 混合版总区间中位数 / µs | 逐例加速比的中位数 |
| --- | ---: | ---: | ---: |
| 1,512,1024,128 | 566.34 | 117.94 | 4.66× |
| 1,1024,4096,128 | 4160.69 | 425.19 | 9.64× |
| 1,8192,257,40 | 1343.80 | 505.94 | 2.72× |

加速比先对每例计算 Vector/混合版，再取中位数，因此不能直接用表中两列中位数相除。24 例均变快，最小逐例加速比约 1.99×。这是已测输入的设备计时，新赛事成绩仍待验证。分布局数据见 [cube-performance-data.json](cube-performance-data.json)。

## 已通过的独立原型

原型源 SHA256 `26db80dc1981ec3fc0332e6bc875168c52d665fcc751937ca72581839f78a8af`，A3 / Ascend910_9362 / CANN 9.0。普通回归 72 个分块、48 个精度、24 个大型短 K 用例通过；大型用例再次运行、benchmark 与 profile 均通过。冷捕获、同图连续调用、双 stream 捕获重放与独立 C++ 动态库冷捕获，分别通过 72/48/248/24 例集合。

直接调用的三种捕获模式分配/释放各 5,488 个缓冲，登记 1,568 次图销毁回调，392 次普通预热同步，无内部 ACL 错误。共享库测试核验独立调用、数值与保护区，不包含这些内部资源计数。

## 当前优化方向

Scores 的控制与库调用成本较高，下一步考虑扩大 N 分块，减少 Matmul 上下文切换。M=8192 时 Finish 占总区间约 42%，其中约 87% 为 Scalar，优先评估保持精度的向量补偿树形归约。已准备高/低分量归约原型，用 TwoSum 恢复加法舍入误差；本地 252 组、2,100 个输出相对 math.fsum golden 全部通过，覆盖尾块、多 batch、负值、抵消与不同量级。这只是 CPU 模型检查，原型未上板、未集成进当前主实现；数学构件参考 [Ogita/Rump/Oishi, Accurate Sum and Dot Product](https://www.tuhh.de/ti3/paper/rump/OgRuOi05.pdf)。长 K 还需单独验证分块补偿及近零抵消，暂时保留 Vector 的已验证路径。
