# 长 K Cube 检查点（2026-10-03）

历史记录：本页描述当时的实现和验证范围；当前版本见 [单次启动检查点](../single-kernel.md)。

历史说明：本文件记录 `9740234` 的两次启动设备实验。该版本违反赛事“每次迭代恰好一个 kernel”规则，不能作为可提交方案；后续单次启动修复见 [新检查点](../single-kernel.md)。以下保留原始实验数据，设备性能不能当作赛事成绩。

候选新增 64×64 的长 K Cube 路径，以 128-K 请求计算 FP32 得分块，并逐元素补偿跨 K 累加；完整 K 完成后才取 N 最大值。任务沿 batch、M 和受限的 N 分区分配，每个分区独立保存行最大值，Finish 先逐行合并 N 分区，再以高/低补偿树求和 M。N 分区数量按可用核数限制，用户工作内存为 `4*B*M*nGroups` 字节；Finish 复用 low 缓冲做 N 合并输入，最大自有 UB 仍为 176 KiB + 32 字节。

实际分派为 K>128、M≥32、N≥128、B*M*N*K≥2^23。原有短 K Cube 分派、32×64 Scores 和 Vector 计算体保留；run_kernel ABI、输入不变与图捕获所有权保持。候选源码 SHA256：`589aff63300fcfd9f153725a7de579e8cca04e58320f897838ca686913b13df5`；对照为 `fc8c8fc`，源码 SHA256 `41e78bd99e00d44a35420555c05a7638b56c05fd23c6ab3cedeae854d7526768`。启动方式已被赛事 profiling 规则拒绝，不提 PR。

## 设计对照

隔离实验保留现有 MIX Matmul 接口，先比较 full-K、512-K 补偿和128-K 补偿，再比较沿 M 分工和 M/N 二维任务。完整 K 在跨 K 抵消和不同量级输入上失败；512-K 补偿通过首轮 64 例，但新增的“抵消发生在一个 512-K 分段内”的 8 例全部失败。因此两者未采用，保留 128-K 补偿。

只沿 M 分工时，128-K 版本在 `(1,129,1024,8192)` 上约 7.26 ms，接近 Vector 的 7.59 ms。二维原型通过 72/72，三个代表形状约快 9.0/13.0/4.6 倍。接入候选进一步限制 N 分区以减少中间内存，其结果以以下独立实测为准；原型收益不能直接作为候选或赛事收益。完整原始设计报告见 [JSON](long-k-design-data.json)，可复现实验见 [生成器说明](../../solution/experiments/long_k/README.md)。

## 实际候选验证

- 本地 656/656：原 584 例加上 72 个实际进入长 K Cube 的用例。Host 地址空间、ASan/UBSan、布局、尾部、输入不变、输出保护区、重复确定性通过；最大误差/容差比 0.00373936。CPU Matmul 使用 FP64，不验证真实 Cube 舍入或流水线。
- 实际 Finish 独立 756 例 / 6,300 输出通过，覆盖 1/2/7 个 N 分区、逐行不同分区获胜、M 尾部、全负、抵消、不同量级和 batch 复用，对照 `math.fsum`。
- A3 / CANN 9.0 / dav-2201 目标 ASC 编译和共享库链接成功。72 个 long-cube 用例在普通、冷捕获、同图连续调用、双 stream 图重放、独立 C++ 动态库冷捕获五模式全部通过。两类型、四布局、K=256/392/1024/8192、M/N 尾部、1/20 核、抵消和不同量级均覆盖；各模式最大误差/容差比 0.00116811。
- 另测 24 个实际短 K Cube 大 M 用例和 32 个小型 Vector 用例，全部通过。直接 runner 长 K 四模式共分配/释放 1,296 个缓冲，error=0；冷捕获、双 stream 捕获无 Host 内部同步。没有重跑完整历史设备回归。

## 同轮性能
